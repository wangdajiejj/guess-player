> 运动：足球 ｜ 平台：微信小程序（原生） ｜ 后端：微信云开发（云数据库 + 云函数）
> 文档状态：第 1 步产出 ｜ 后续步骤见 docs/02-database.md ~ docs/05-deploy.md

---

## 1. 产品概述

### 1.1 一句话描述

一个 Wordle 式的足球球员竞猜小程序：每天一名球员作为答案，玩家从 500 人库里通过「搜索选人」最多猜 8 次，每次猜测回填 8 条属性线索并用双色/灰阶 + 升降箭头反馈，逐步逼近答案；猜中或耗尽次数后进入结果页，可生成战绩方块图分享。

### 1.2 目标用户

| 分层 | 画像 | 核心诉求 |
| --- | --- | --- |
| 核心用户 | 18-35 岁男性为主，五大联赛重度观众，FPL / FIFA Ultimate Team 玩家 | 每日签到式挑战、炫耀球识、社交分享 |
| 泛用户 | 世界杯/欧洲杯期间观赛的泛球迷 | 低门槛（无需手动输入全名，搜索候选即可）上手 |
| 传播节点 | 球迷群、朋友圈 | 战绩图可分享、不剧透答案 |

### 1.3 差异化定位

- **门槛更低**：不像 Wordle 需要拼写字幕，本作是「选人」而非「填字」，中国球迷不会因为记不住外文名被卡住（支持中文名/英文名/别名/绰号搜索）。
- **信息密度更高**：8 个字段 + 生涯趣事 + 网络热梗，比 Wordle 的字母反馈更耐推演。
- **社交友好**：战绩图仅展示颜色方块（绿/黄/灰 + 箭头），不泄露答案，可安全发群。

## 2. 核心玩法规则（可裁定文本）

### 2.1 模式

| 模式 | 答案选取 | 次数限制 | 每日限制 | 是否计入排行榜 |
| --- | --- | --- | --- | --- |
| **每日挑战 Daily** | 由「日期种子 + 用户匿名标识」伪随机抽取，**每人每天答案不同** | 8 次 | 每天 1 局（可重看，不重复计分） | 是 |
| **无限模式 Endless** | 真随机（客户端不可预测，由云函数下发） | 8 次 | 不限 | 否（只累计本地统计） |

> **每日种子算法**：`hash(SALT + 日期 yyyy-MM-dd + "|" + openid) % 答案池长度`，保证同一用户同一天答案固定、跨天换题、答案不落库。`meta/daily_salt.mode = 'global'` 可切回「全球同答案」（详见 `docs/03-algorithm.md §5`）。
>
> **答案池分档**：每日一题只从「知名度 ≥ 4 星」的 250 人里抽；自由练习放宽到「≥ 3 星」的 500 人。理由：冷门球员当每日答案时，没听说过的人靠线索也推不出名字，只剩挫败（详见 `docs/03-algorithm.md §5.2`）。

### 2.2 单次对局流程

1. 进入游戏页 → 云函数 `gameStart` 下发 `gameId`（不含答案）。
2. 底部「选择球员」按钮 → 弹出搜索面板，`<input>` 输入关键字（中/英/别名/绰号/拼音），实时模糊匹配候选列表（最多展示 30 条）。
3. 选中球员 → 云函数 `gameGuess` 校验 + 比对 → 返回 8 个字段的反馈结果，追加一行线索。
4. **（可选）点线索卡上的任意标签** → 弹出候选面板，按这条线索筛出还符合条件的球员，可直接点选提交下一次猜测（见 §2.3.1）。
5. 命中（猜测 id === 答案 id）或次数用尽 → 云函数返回结果 + 答案完整数据 → 跳转结果页。
6. 结果页：答案球员卡（程序化头像/国籍/俱乐部/位置/简介/趣事/热梗）+ 战绩方块图 + 「再来一局」「分享战绩」。

### 2.3 反馈规则（必须严格统一，前后端共用一份实现）

对每个字段比对猜测球员 `G` 与答案球员 `A`：

| 字段 | 绿（green） | 黄（amber） | 灰（gray） | 数值箭头 |
| --- | --- | --- | --- | --- |
| `nationality` 国籍 | 完全相同 | — | 不同 | — |
| `club` 俱乐部 | 完全相同 | 同联赛（联赛相同但俱乐部不同） | 不同 | — |
| `league` 联赛 | 完全相同 | — | 不同 | — |
| `position` 位置 | 完全相同（细分位置一致，如均为「右边锋」） | 同位置大类（GK/DF/MF/FW 相同，细分不同） | 大类不同 | — |
| `age` 年龄 | 完全相等 | 相差 ≤ 2 岁 | 相差 > 2 岁 | ↑ 猜的比答案大 / ↓ 小 / = 相等 |
| `height_cm` 身高 | 完全相等 | 相差 ≤ 3 cm | 相差 > 3 cm | ↑ / ↓ / = |
| `preferred_foot` 惯用脚 | 完全相同 | — | 不同（左脚↔右脚） | — |
| `shirt_number` 球衣号 | 完全相等 | 相差 ≤ 3 号 | 相差 > 3 号 | ↑ / ↓ / = |

**补充裁定（避免歧义）：**

1. **年龄计算口径**：`age = 按生日是否已过计算的实际周岁`，基准日期取「对局所在自然日」；传奇球员（退役）同样据此计算。数据库只存 `birth_date`，年龄在云函数实时算，避免数据过期。
2. **年龄/身高同层优先**：先判定代数差，再叠加黄/灰。相等时必定是绿色 + `=`。
3. **位置大类映射**：`GK` 门将；`DF` 中后卫/边后卫/清道夫；`MF` 后腰/中场/前腰/边前卫；`FW` 中锋/影锋/边锋。
4. **国籍判定**：以球员代表的国家队为准（数据库 `nationality` 单一国籍；双重国籍存主要代表队，别名里补充搜索词）。
5. **未知/缺失字段**：统一按灰处理，`height_cm` / `shirt_number` 为 0 或 null 时显示「—」，不参与箭头比较。
6. **猜测去重**：同一局内重复猜同一名球员，后端返回 `DUPLICATE` 错误，前端 toast「已经猜过 TA 了」，**不消耗次数**。
7. **候选池一致性**：猜测目标必须存在于当前启用的球员池（可猜 500 人），但答案只从「答案池」（知名度阈值 ≥ 3 星）里抽，保证玩家一定能搜到答案。
   ⚠️ 「玩家一定能搜到答案」依赖候选池下发的是**完整**题库：`getPlayers` 若被分页上限截断，
   答案落在截断区外就会变成死题。由 `test-flow.js` 的「下发条数正确」守着，
   详见 `docs/04-testing.md §5` 的「候选池被静默截断」条。

### 2.3.1 点线索标签筛选候选池（v1.1 新增）

每行线索卡上的 8 个标签都可点击。点一下，就按这条线索过滤本地候选池，列出**还符合条件**的球员，可直接点选提交下一次猜测。

三态语义严格对应 §2.3 的判定表：

| 标签 | 语义 | 点击后的筛选规则 |
| --- | --- | --- |
| 绿 | 与答案完全一致 | 正向精确：点「右脚」→ 名单只剩右脚球员；点「阿根廷」→ 只剩阿根廷人 |
| 黄 | 俱乐部同联赛 / 位置同大类 / 数值差在公差内 | 正向放宽：俱乐部黄 → 同联赛的人（且排除被猜的那个俱乐部）；位置黄 → 同大类（且排除被猜的细分位置）；数值黄 → 公差区间 + 箭头方向 |
| 灰 | 与答案不同 | 反向排除：点「巴西」→ 名单里不再出现巴西球员；数值灰只知道大小方向，按不等式筛 |

**默认只启用被点的那一条**。面板里可以继续勾选其它线索叠加；同一字段的多条线索会自动合并（绿优先于黄，黄优先于灰）。

- 筛选**全部在客户端完成**，只用玩家已经看得见的信息（标签颜色 + 箭头），不请求任何服务端私有数据，也不改变判定结果 —— 它只是替玩家做「哪些人还符合条件」的穷举。
- ★ **正确性不变量：筛选结果一定包含正确答案。** 每条约束都只是答案的「必要条件」，不会把答案自己排掉。由 `scripts/test-candidates.js` 用真实题库跑 40 局、1.1 万次筛选守着。
- 实测：8 次机会用完后把全部线索叠加，平均只剩 **1 人**。所以默认不叠加 —— 全叠上去等于一键看答案，得让玩家自己选。

**列表里每名候选球员摊开展示全部 8 项线索**（国籍 / 俱乐部 / 联赛 / 位置 / 年龄 / 身高 / 球衣号 / 惯用脚），两列排布，字段顺序与线索卡、结果页、分享图**共用 `theme.CLUE_META` 同一份表**，所以纵向扫一列就能和已知线索逐项比对。年龄不存库，同样按对局自然日实时算（和筛选时用的是同一个 `calcAge`）。

- 字段缺值时显示 `—`，不留空白也不抛错。
- 列表渲染有 100 人上限（每人 8 项 = 16 个节点，500 人无筛选时会掉帧）；超限时在面板底部**明说**截断了多少人，并提示点标签收窄 —— 不做静默截断。正常玩法点一两条线索就收到十几人以内，碰不到。
- ⚠️ 副作用（已知并接受）：候选人的属性从 3 项变成 8 项，等于把「该猜谁」的判断依据摊在桌面上，**难度比 v1.1 低**。这是产品取舍，不是 bug。

### 2.4 计分与段位（轻量）

- 单次得分：`score = max(0, (9 - 使用次数) * 100)`，即 1 次猜中 = 800 分，8 次猜中 = 100 分，失败 = 0。
- 每日挑战连胜 streak 额外加成 `+ streak * 20`（上限 +200）。
- 本地统计（存 storage）：总局数、胜率、平均用次数、当前连胜、最长连胜、历史最佳。

### 2.5 音效与振动（v1.1 新增）

| 时机 | 音色 | 设计意图 |
| --- | --- | --- |
| 点线索标签 / 切条件 / 点按钮 | `tap` 660Hz 三角波 50ms | 轻，不抢注意力 |
| 面板打开 / 关闭 | `open` 上行扫频 / `close` 下行扫频 | 给"抽屉"一个方向感 |
| 猜中 | `hit` C5-E5-G5-C6 上行琶音 | 唯一的"奖励音"，明亮 |
| 猜错但还有机会 | `miss` 420→300Hz 短下滑 | 不打击人 |
| 机会用完 | `lose` 双音下沉 | 收场，但克制 |

- **零音频素材**：全部由 `wx.createWebAudioContext()` 实时合成（振荡器 + 指数包络），不增加包体，也不涉及音乐版权 —— 与头像"程序化绘制"是同一个思路。
- 基础库低于 2.19.0 或设备不支持时**静默降级**，游戏功能不受影响；设置页会自动把开关置灰并说明原因。
- 振动与音效**各自独立开关**，默认都开，只存本机。
- 合成参数的安全区间（频率 20~8000Hz、单音时长 ≤ 0.8s、峰值音量 ≤ 0.3、同时发声估算 ≤ 0.5）由 `scripts/test-sfx.js` 守着，防止把音量写成 0.9 那种"当场卸载"的事故。

| P0-12 | 音效（程序合成，零素材）+ 独立开关 | 6 种音色，不支持时静默降级（§2.5） |

### P1 — 紧随其后（v1.1）

- 本地统计看板（胜率/连胜/分布图）
- 好友排行榜（云开发 `openid` 互通，只展示昵称+步数式战绩）
- 难度开关（答案池限制为五大联赛现役 / 全量含传奇）
- 球员数据月度更新机制（后台录入 + 数据库版本 `meta` 集合）

### P2 — 后续规划（不做在首版）

- 篮球/NBA 版、F1 车手版（同一套引擎，换数据源）
- 「提示卡」消耗机制 + 广告变现阶段
- UGC 出题：玩家自定义球员/custom range
- 赛季通行证、球迷会 grouping

### 明确不做（Out of Scope）

- ❌ 不做用户账号体系 / 手机号授权登录（只用小程序匿名 `openid`）
- ❌ 不做实时对战 / 房间
- ❌ 不做真实图片社交流（评论、点赞流）
- ❌ 不做题库在客户端（答案必须云端下发，防止反编译作弊）

### 4.3 关键交互状态机（游戏页）

| 状态 | 说明 | 可操作 |
| --- | --- | --- |
| `LOADING` | 拉取 gameId | 无（骨架屏） |
| `PLAYING` | 剩余 >0 且未命中 | 搜索、放弃 |
| `SUBMITTING` | 请求中 | 按钮禁用，防重复点击 |
| `WON` / `LOST` | 终局 | 跳转结果页 |
| `OFFLINE` | 网络失败 | 重试按钮，本地草稿保留 |

### 4.4 异常流程

- **云函数调用超时/失败**：保留本地线索，允许重试；不消耗次数（次数是服务端计）。
- **今日已完成**：首页显示「今日战绩 ✅ x/8」，入口变为灰色 + 引导无限模式。
- **数据版本过期**：首页底部轻提示「题库更新至 2026-xx-xx」。

## 5. 技术架构

### 5.1 架构图

```
┌──────────────── 微信小程序（原生 WXML/WXSS/JS）───────────────┐
│  pages/ 首页 游戏页 结果页 帮助页 设置页                         │
│  utils/ compare.js(纯函数) search.js storage.js theme.js       │
│  components/ search-sheet/ clue-row/ result-card/ share-canvas │
└───────────────────────┬────────────────────────────────────────┘
                        │ wx.cloud.callFunction
┌───────────────────────▼──────── 微信云开发 ────────────────────┐
│  云函数                                                         │
│   ├─ gameStart   幂等开局，按模式/日期求答案，返回 gameId         │
│   ├─ gameGuess   校验 + 比对 + 写回，返回 8 字段反馈             │
│   ├─ getPlayer   结果页拉取答案详情（含趣事/热梗）               │
│   └─ getPlayers  首次/增量拉取候选池，写本地缓存                  │
│  云数据库                                                        │
│   ├─ players    500 条球员（猜池 + 答案池）                      │
│   ├─ games      对局记录（含答案，权限：仅创建者可读写）           │
│   └─ meta       题库版本 / 每日种子 SALT                         │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 为什么答案必须放在云端

客户端内置答案 = 反编译可读 = 排行榜失去意义。因此：**候选池（500 人全部字段）可下发到客户端做搜索**，但**答案 id 只在 `games` 集合中、且通过云函数比对后才暴露**。搜索面板需要的属性也让 hazard 可控（泄漏的是公开球员资料，不是答案本身）。

> ⚠️ 注意：即使是云函数，返回给客户端的 `games` 文档若含 `answerId` 也会被抓包看到。因此 `getPlayer` 只在**终局**后才返回答案详情，`gameGuess` 的返回值里绝不出现 `answerId`。

### 5.3 关键技术方案

| 议题 | 方案 |
| --- | --- |
| 搜索 | 候选池一次性下发（500 条实测 169.7 KB）→ 存 `storage` → 前端本地搜索，0 网络延迟；带版本号增量更新（`version` 相同则不下发） |
| 中文搜索 | `name_cn` 直接 `includes`；英文名转小写 `includes`；`aliases` 数组遍历；额外建立 `searchIndex` 字段（拼接去空格小写串）一次 `indexOf` 搞定 |
| 数百次 CDN 拉取 | `getPlayers` 返回 `updatedAt` 版本号，前端 storage 比对，一致则不传输 |
| 战绩图 | `canvas type="2d"` 离屏绘制 → `wx.canvasToTempFilePath` → `wx.saveImageToPhotosAlbum` / `onShareAppMessage` |
| 主题 | 深绿球场配色 + A 股式直觉的红涨绿跌？**否**——沿用国际 Wordle 语义：绿=正确、黄=接近、灰=错误（规避认知冲突） |

## 7. 合规与版权 —— 关键决策（务必确认）

### 7.1 球员形象 —— **最终决策（2026-10-11）：程序化绘制，不用任何位图**

**放弃 AI 生成球员像，改为纯 CSS 程序化绘制**（队色渐变 + 球衣斜纹 + 姓氏首字 + 位置徽章）。

| 弃用理由 | 说明 |
| --- | --- |
| **肖像权** | 《民法典》1019 条保护"可识别的外部形象"，AI 生成同样不豁免。主流工具刻意拒绝生成可识别的真实球员（Soku AI 官网明示） |
| **搜不到现成素材** | 网上免费商用的只有通用足球插画，没有可识别的特定球星 |
| **性价比低** | 头像实际渲染仅 36~84px，照片细节看不清；200 张图约 10MB 存储 + CDN |
| **合规成本** | AI 生成内容按《标识办法》(2025-09-01) 需显式角标 + 隐式元数据 |

**同时规避的商标风险**：球衣上不出现俱乐部徽章、赞助商 Logo、球衣号码数字
—— 号码是游戏线索，画在图上等于剧透，程序化方案天然不会有这个问题。

实现见 `miniprogram/components/player-badge/`，规范见 `docs/02-database.md §5`。
零存储、零加载、无版权风险、不需要 AI 标识。

> 若将来要做真实照片背景，可用 Pixabay Content License 素材（链接存档在
> `docs/02-database.md §5.4`），但**头像仍建议保持程序化** —— 真人头像的肖像权
> 风险不会因为"图是从网上免费下的"而消失。

### 7.2 隐私合规

- 不申请 `scope.userInfo`（头像昵称）以外的任何权限；
- 排行榜用 `wx.cloud` 的匿名 `openid`，不索取手机号；
- 战绩图生成只写入用户主动触发的相册保存，不静默写；
- 隐私协议必需在 MP 后台「用户隐私保护指引」中勾选，并在设置页提供查看入口（详见第 5 步）。

### 7.3 类目选择 ✅ 已定

**最终类目：工具类 → 效率。**

| 候选 | 结论 |
| --- | --- |
| 游戏 → 休闲游戏 | ❌ 小程序「游戏」类目不向个人主体开放，选了必拒 |
| 体育 → 运动健身 | ❌ 会被要求提供体育行业相关资质 |
| **工具 → 效率** | ✅ **采用**。代价是文案必须去游戏化（详见 `docs/05-deployment.md` §7.2） |

对应地，UI 文案已统一：「每日挑战 → **每日一题**」「无限模式 → **自由练习**」，
对外不出现"游戏/通关/闯关/排行榜"等字样。
