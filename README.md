# guess-player · 足球猜球员

一个微信小程序的足球版 Wordle：每天一位神秘球员，你有 **8 次机会**把他猜出来。

每次猜测会给出 **8 行线索** —— 国籍 / 俱乐部 / 联赛 / 位置 / 年龄 / 身高 / 惯用脚 / 球衣号，
每一行用**三色**告诉你差多远：

| 颜色 | 含义 |
| --- | --- |
| 🟩 绿 | 完全一致 |
| 🟨 黄 | 接近（俱乐部同联赛 / 位置同大类 / 数值在公差内，带 ↑↓ 箭头） |
| ⬜ 灰 | 完全不对（数值类同样带箭头） |

题库 **500 人**（现役 292 + 退役传奇 208，覆盖 52 个国籍 / 78 家俱乐部 / 14 个联赛），
含每日挑战与无限模式，可生成战绩分享图。答案池分档：每日一题 250 人（知名度 ≥ 4 星），
自由练习 500 人（≥ 3 星）。

> 上手指南见 **[README-启动.md](README-启动.md)**，设计和算法细节在 `docs/` 下五份文档。

## 技术栈

- **微信小程序原生**（WXML / WXSS / JS，无第三方框架）
- **微信云开发**：云数据库存题库与对局，云函数做判定，云存储不用
- 零素材：头像由队色渐变现画，音效由 WebAudio 现场合成

## 快速开始

```bash
# 0. 装好微信开发者工具，导入本目录
# 1. 想立刻看效果、不想配云环境：
scripts\开启本地测试.bat          # 本地模式：不连云、不用 AppID、不用备案
# 2. 要真上线：
#    README-启动.md 的「路线 B」—— 开通云开发 → 填 ENV_ID → 建集合 → 导题库 → 传云函数
```

⚠️ `miniprogram/app.js` 里的 `ENV_ID` 和 `project.config.json` 里的 `appid`
是**必须换成你自己**的两处，其余不用改。

## 两条架构红线

1. **答案绝不下发客户端。** `games.answerId` 只留在云数据库；云函数返回的 `verdict`
   只有颜色和箭头，不含答案。比对逻辑在云函数里，客户端不做判定 ——
   否则反编译后遍历 500 人候选池就能把每天的答案试出来。
2. **本地测试模式不能带进提审包。** `scripts/开启本地测试.bat` 会把比对逻辑和答案池
   临时拼进客户端（为了没云环境也能自测），提交审核前必须跑
   `scripts/关闭本地测试-提审前必点.bat` 切回来。

细节见 `docs/03-algorithm.md §6`。

## 关于球员形象

球员头像**不是照片**，也不使用任何位图素材：由 `player-badge` 组件读取球员所属球队的
主色 / 副色，现场画一个渐变圆牌 + 姓氏首字 + 位置徽章。

这样做的原因（以及为什么放弃 AI 生成头像）记录在 `docs/01-PRD.md §7.1`：
涉及真人的肖像权与合规风险，且主流工具不接受生成可识别真人。

> `assets/` 目录是 2026-10-10 那版「AI 生成肖像」方案的**历史残留**，已废弃、
> 不被任何代码引用，且**不在本仓库内**（已列入 `.gitignore`）——
> 其内容为可识别真人的 AI 肖像，不适合公开分发。
